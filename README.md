# РУДН-бот (v2)

Личный Telegram-бот для учёбы: расписание (верхняя/нижняя неделя), дедлайны Д/з и лаб,
экзамены и зачёты, предметы с материалами и файлами, страница МФЦ / деканат.
Стек: Python 3.13, aiogram 3, aiohttp (раздача файлов по ссылке и health-check).

## Запуск

```bash
pip install -r requirements.txt
BOT_TOKEN=... OWNER_ID=... python bot.py
```

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен бота (обязательно) |
| `OWNER_ID` | Telegram id владельца: добавление заданий, загрузка файлов, сервис |
| `DATA_FILE` / `DATA_DIR` | где лежит база; по умолчанию `/data/data.json` (volume), иначе `data.json` из репозитория |
| `PUBLIC_BASE_URL` / `RAILWAY_PUBLIC_DOMAIN` | публичный адрес для ссылок на файлы |
| `FILE_LINK_SECRET` | секрет подписи ссылок на файлы (по умолчанию — токен) |
| `PORT` | порт HTTP (Railway задаёт сам) |

## Структура

```
bot.py                 — тонкий запуск: asyncio.run(rudn.core.app.main())
config/
  schedule.json        — расписание (перенесено из старого bot.py без изменений) и якорь недели
  subjects.json        — порядок предметов, переименования, синонимы, шаблон разделов, общие ссылки (ТУИС)
data.json              — стартовая база (копируется на volume, если там пусто)
rudn/
  core/                — стабильное ядро, при добавлении фич не меняется
    app.py             — сборка реестра, роутеров, команд, запуск polling + HTTP
    registry.py        — реестр фич и самопроверка (префиксы, команды, ≤64 байт)
    ui.py              — кнопки, навигация «⬅ Назад / 🏠 Меню», одно «живое» меню, Ctx
    home.py            — главное меню из кнопок и сводок фич
    storage.py         — загрузка/нормализация/атомарная запись data.json
    tasks.py           — логика заданий: виды, сроки, группы дедлайнов, экзамены
    timeutil.py        — московское время, недели, форматирование дат
    pending.py         — ожидание ввода текста (15 минут)
    config.py, web.py  — настройки; раздача файлов по подписанной ссылке
  features/            — фичи, каждая в своём файле
    __init__.py        — СПИСОК ПОДКЛЮЧЁННЫХ ФИЧ
    schedule.py        — 📅 Сегодня / ⏭ Завтра / 🗓 Неделя (d:, w:)
    deadlines.py       — 🔥 Дедлайны (dl:)
    exams.py           — 🎓 Экзамены (ex:)
    subjects.py        — 📚 Предметы, разделы, файлы (subs:, s:, file:)
    pages.py           — инфо-страницы из data.json, например 🏛 МФЦ (p:)
    admin.py           — владелец: ➕ Добавить, ⚙️ Сервис, загрузка файлов, восстановление (add:, adm:, up:, rs:)
tests/                 — офлайн-тесты (pytest), Telegram не нужен
```

## Как добавить новую фичу (например, «ТУИС» или «Напоминания»)

1. Создай `rudn/features/<имя>.py`:

```python
from rudn.core.registry import CommandSpec, Feature, MenuButton
from rudn.core.ui import Ctx, b, nav

async def on_tuis(ctx: Ctx, args: list[str]) -> None:
    # args — части callback_data после префикса: "tu:grades" → ["grades"]
    await ctx.show("📊 <b>ТУИС</b>\n…", [[b("Оценки", "tu:grades")], nav()])

async def cmd_tuis(ctx: Ctx) -> None:
    await on_tuis(ctx, [])

feature = Feature(
    name="tuis",
    callbacks={"tu": on_tuis},                       # свой уникальный префикс
    menu=[MenuButton("📊 ТУИС", "tu", order=35)],    # кнопка в главном меню
    commands=[CommandSpec("tuis", "ТУИС", cmd_tuis)], # необязательно
    summary=lambda ctx: ["📊 Новых оценок: 0"],       # строка в главном меню, необязательно
    summary_order=40,
)
```

2. Допиши одну строку — имя файла — в `rudn/features/__init__.py` → `FEATURES`.
3. `python -m pytest -q tests` — тесты сами обойдут все экраны новой фичи.

Что важно знать:
* При запуске реестр проверяет: префиксы и команды уникальны, у каждой кнопки меню есть
  обработчик, `callback_data` ≤ 64 байт. При конфликте бот **не стартует** и пишет, что с чем
  конфликтует, — молча сломаться нельзя.
* Кнопка с неизвестным префиксом (старое сообщение) не ломает бота: «Меню обновилось» + главное меню.
* Ошибка внутри фичи ловится ядром: всплывашка «Ошибка» и главное меню; сводка фичи, упавшая
  с ошибкой, просто не показывается.
* Кнопка на другую фичу — через `maybe(text, data)`: если той фичи нет, кнопка не появится.
* «Назад»: `nav(back)`; чтобы вернуться туда, откуда пришли, добавь к данным кнопки `|<куда>`
  (`with_back("d:2026-10-27", "s:3")`), а в обработчике используй `ctx.back`.
* Ввод текста: `ctx.wait_text("<state>", keep=("<префикс>",), ...)` + `text_states={"<state>": handler}`.
  Через 15 минут ожидание сгорает; любая другая кнопка его отменяет.
* Фоновые задачи (например, напоминания) — отдельная фича со своим `router` или запуском в
  `on_startup`; ядро для этого менять не придётся (кроме, при необходимости, одного хука запуска).

## Формат data.json

Формат прежний; v2 добавляет только **необязательные** поля. Старые файлы читаются как есть,
а файл, записанный v2, читает и старая версия (проверено тестом `test_rollback.py`).

```jsonc
{
  "pages":    [{"title": "🏛 МФЦ / деканат", "text": "…", "links": [{"title": "…", "url": "…"}]}],
  "subjects": [{"name": "Химия", "teacher": "…", "contacts": "…", "description": "…",
                "sections": [{"title": "📖 Учебная литература", "text": "", "links": [],
                              "files": [{"file_id": "…", "name": "лекция.pdf", "mime": "application/pdf"}]}]}],
  "events":   [{"day": 26, "month": 10, "year": 2026, "date": "2026-10-26", "text": "…", "created": "…"}],
  "homework": [{"id": 0, "subject": "Химия", "subject_idx": 3, "text": "…",
                "day": 27, "month": 10, "year": 2026, "date": "2026-10-27",
                "done": false, "created": "…",
                // новое, всё необязательно:
                "kind": "lab",          // нет поля = "hw" (Д/з); "lab" — лаба; "exam" — экзамен/зачёт
                "exam_type": "credit",  // для kind=exam: "exam" | "credit" (зачёт)
                "time": "10:00", "place": "ЕГФ ауд. 375",  // для экзаменов
                "done_at": "…"}]        // когда отмечено выполненным
}
```

Нормализация при загрузке такая же, как раньше (порядок предметов, переименование, шаблон
разделов) + выдаёт `id` заданиям без id. Страницы «📅 Расписание» и «📝 Дедлайны и экзамены»
в data.json остаются, но в меню скрыты — их заменили отдельные экраны.

## Откат на старую версию

Старая версия сохранена тегом **`stable-v1`** (коммит `5f8da79`).

* Локально посмотреть/запустить: `git checkout stable-v1`.
* Откатить прод: `git checkout main && git reset --hard stable-v1 && git push --force-with-lease origin main`
  (или мягко: `git revert` коммитов v2). Railway пересоберёт старую версию; база совместима в обе стороны.
* Тег в GitHub: `git push origin stable-v1`.

## Деплой

Railway: команда запуска та же — `python bot.py`, тот же `requirements.txt`, те же переменные.
Миграции данных не нужны. Деплой = влить ветку `v2` в `main` и запушить:

```bash
git push origin stable-v1          # сохранить тег старой версии
git checkout main && git merge --ff-only v2 && git push origin main
```

Перед пушем: `python -m pytest -q tests`. Бэкап базы в любой момент — `/backup` (владелец).

## Команды

Видимые: /start, /today, /tomorrow, /week, /deadlines, /exams, /subjects.
Скрытые: /menu, /cancel, /status, /backup (два последних — только владелец).
Файл документом → выбрать предмет и раздел. `data.json` документом → восстановление (с бэкапом текущей).
