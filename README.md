# РУДН-бот (v2)

Личный Telegram-бот для учёбы: расписание (верхняя/нижняя неделя), дедлайны Д/з и лаб,
экзамены и зачёты, предметы с материалами и файлами, страница МФЦ / деканат.
Стек: Python 3.13, aiogram 3, aiohttp (раздача файлов по ссылке и health-check).

## Запуск

```bash
pip install -r requirements.txt
BOT_TOKEN=... OWNER_ID=... python bot.py
```

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен бота (обязательно) |
| `OWNER_ID` | Telegram id владельца: добавление заданий, загрузка файлов, сервис |
| `DATA_FILE` / `DATA_DIR` | где лежит база; по умолчанию `/data/data.json` (volume), иначе `data.json` из репозитория |
| `PUBLIC_BASE_URL` / `RAILWAY_PUBLIC_DOMAIN` | публичный адрес для ссылок на файлы |
| `FILE_LINK_SECRET` | секрет подписи ссылок на файлы (по умолчанию — токен) |
| `PORT` | порт HTTP (Railway задаёт сам) |

    app.py             — сборка реестра, роутеров, команд, запуск polling + HTTP

    pending.py         — ожидание ввода текста (15 минут)

  features/            — фичи, каждая в своём файле
    __init__.py        — СПИСОК ПОДКЛЮЧЁННЫХ ФИЧ
    schedule.py        — ⏭ Завтра / 🗓 Неделя, экран дня (d:, w:); сводка = расписание на сегодня

    deadlines.py       — 🔥 Дедлайны (dl:)
    exams.py           — 🎓 Экзамены (ex:)
    subjects.py        — 📚 Предметы, разделы, файлы (subs:, s:, file:)
    pages.py           — инфо-страницы из data.json, например 🏛 МФЦ (p:)

## Как добавить новую фичу (например, «ТУИС» или «Напоминания»)

1. Создай `rudn/features/<имя>.py`:

```python
from rudn.core.registry import CommandSpec, Feature, MenuButton
from rudn.core.ui import Ctx, b, nav

async def on_tuis(ctx: Ctx, args: list[str]) -> None:
    # args — части callback_data после префикса: "tu:grades" → ["grades"]
    await ctx.show("📊 <b>ТУИС</b>\n…", [[b("Оценки", "tu:grades")], nav()])

async def cmd_tuis(ctx: Ctx) -> None:
    await on_tuis(ctx, [])

feature = Feature(
    name="tuis",
    callbacks={"tu": on_tuis},                       # свой уникальный префикс
    menu=[MenuButton("📊 ТУИС", "tu", order=35)],    # кнопка в главном меню
    commands=[CommandSpec("tuis", "ТУИС", cmd_tuis)], # необязательно
    summary=lambda ctx: ["📊 Новых оценок: 0"],       # сводка; на главный попадает, только если имя фичи в home.HOME_SUMMARIES
    summary_order=40,
)
```

2. Допиши одну строку — имя файла — в `rudn/features/__init__.py` → `FEATURES`.
3. `python -m pytest -q tests` — тесты сами обойдут все экраны новой фичи.

Что важно знать:
* При запуске реестр проверяет: префиксы и команды уникальны, у каждой кнопки меню есть
  обработчик, `callback_data` ≤ 64 байт. При конфликте бот **не стартует** и пишет, что с чем
  конфликтует, — молча сломаться нельзя.
* Кнопка с неизвестным префиксом (старое сообщение) не ломает бота: «Меню обновилось» + главное меню.
* Ошибка внутри фичи ловится ядром: всплывашка «Ошибка» и главное меню; сводка фичи, упавшая
  с ошибкой, просто не показывается.
* Кнопка на другую фичу — через `maybe(text, data)`: если той фичи нет, кнопка не появится.
* «Назад»: `nav(back)`; чтобы вернуться туда, откуда пришли, добавь к данным кнопки `|<куда>`
  (`with_back("d:2026-10-27", "s:3")`), а в обработчике используй `ctx.back`.
* Ввод текста: `ctx.wait_text("<state>", keep=("<префикс>",), ...)` + `text_states={"<state>": handler}`.
  Через 15 минут ожидание сгорает; любая другая кнопка его отменяет.
* Фоновые задачи (например, напоминания) — отдельная фича со своим `router` или запуском в
  `on_startup`; ядро для этого менять не придётся (кроме, при необходимости, одного хука запуска).

## 📚 Уроки (готовые уроки без ИИ)

Кнопка «📚 Уроки» в меню (только владелец). Уроки — готовые JSON-файлы в
`content/lessons/<предмет>/<id>.json`, никаких внешних API. Урок идёт в **одном
сообщении**, которое правится на месте: объяснение → пример → вопросы → задача на
подумать. Ответ, написанный сообщением, сразу удаляется, а в том же сообщении
появляется «✅ Верно / ❌ Неверно», правильный ответ и пояснение. Кнопки:
`◀️ Назад` / `Далее ▶️` (на последнем блоке `🏁 Итог`), `✖️ Выйти`, `🗑 Сброс`, `🏠 Меню`.

Урок считается усвоенным, если отвечены все вопросы и ≥60 % верно (или вручную
«✅ Отметить усвоенным»; «🔁 Пройти заново» — сброс с подтверждением). Усвоенные
скрыты из списка: «👁 Показать усвоенные», «🔁 Повторить», «↩️ Вернуть в список»
(урок снова в списке и откроется с блока 1, прошлый счёт виден в итоге),
«🗑 Сбросить прогресс урока».
Прогресс — в `data.json` → `lessons`. Уроки с ближайшим сроком (`target`) идут первыми
с подсказкой «⏳ к КР 03.11, осталось N дн.».

### 🗓 План по дням

«📚 Уроки» открывается экраном **«📅 Сегодня (≈N мин)»**: только уроки на сегодня
(1–2 кнопки), «🗓 План по дням», «📚 Все уроки» (полный список — можно взять урок
заранее). Сделал всё — «✅ На сегодня всё» и «➕ Взять следующий урок». Сводка
(на главный не выводится): «📚 Сегодня: Латынь — урок 1 (≈15 мин)». Логика — `rudn/lessons_plan.py`
(чистая функция), план **пересчитывается при каждом показе** по прогрессу:
пропущенное переезжает вперёд, сделанное заранее освобождает дни, новые уроки и
сроки (новый JSON / новая `target`) распределяются сами.

- Уроки группы срока — с сегодня (после 21:00 МСК — с завтра) по день за два до срока;
  день перед сроком — «🔁 Повторение».
- Лимит по расписанию: ≥5 пар → 1 урок, 1–4 пары → 2, нет пар → 3; не больше 2 уроков
  одного предмета в день; уроки размазываются ровно, лёгкие дни берут больше.
- Не помещается → сначала занимается день повторения, потом лимит поднимается по одному
  на самый лёгкий день (до 4), с предупреждением «⚠️ …». Завала на один день нет.
- Предметы перемежаются, порядок внутри предмета (lat-01 → lat-08) сохраняется.
- Срок прошёл или выполнен — уроки идут «без срока», по одному в день.
- Время урока — оценка по объёму (10–15 мин) или поле `"minutes"` в JSON.

Формат файла (id = имя файла, `a-z0-9-`):

```json
{"id": "lat-09", "subject": "Латинский язык", "order": 9, "title": "Название",
 "sources": ["Тема 2, с. 10–11"],
 "target": {"key": "lat-kr1-chat", "label": "КР", "date": "2026-11-03"},
 "blocks": [
  {"type": "explain", "title": "…", "text": "HTML: только <b> <i> <u> <code>"},
  {"type": "example", "title": "…", "text": "…"},
  {"type": "choice", "q": "…", "options": ["a", "b", "c"], "correct": 1, "explain": "…"},
  {"type": "text", "q": "…", "accept": ["ramus mandibulae"], "explain": "…"},
  {"type": "think", "q": "…", "answer": "разбор", "accept": ["необязательно"]}
 ]}
```

Нужно: ≥1 `explain`, ≥1 `example`, 3–6 вопросов (`choice`/`text`), ровно один `think`
последним. Проверка ответа терпимая: регистр, ё/е, ударения, знаки препинания,
кириллические «двойники» латинских букв; в русских ответах прощается одна опечатка,
в латинских — нет (окончание важно, покажется «Почти!»). Битый файл пропускается с
ошибкой в логе; `pytest tests/test_lessons.py` проверяет все файлы.

## 👀 Тестеры (доступ только на просмотр)

- Чужой пишет боту `/start` → ему «📨 Запрос на доступ отправлен владельцу», владельцу приходит
  карточка (имя, @username, ID) с кнопками «✅ Пустить как тестера» / «❌ Отказать».
  Больше чужие ничего не видят и не получают; повторные запросы гасятся (60 с, отказ — 24 ч, не больше 10 открытых).
- `/testers` (или ⚙️ Сервис → 👥 Тестеры) — список тестеров, кнопка «🚫 Отключить», ожидающие запросы.
- Тестер видит всё (расписание, предметы, книги и файлы, дедлайны, экзамены, баллы), проходит уроки —
  прогресс у него свой. Любое изменение → всплывашка «👀 Режим тестера: изменения недоступны».
- Охрана в одном месте: `rudn/core/access.py` (`TESTER_READ` — белый список callback-префиксов,
  `TESTER_COMMANDS`, `TESTER_TEXT_STATES`) + `SandboxStore`: у не-владельца копия данных, запись идёт только
  в `access.json` (рядом с `data.json`, не в git). Новая фича без правила в `TESTER_READ` для тестера закрыта.
- `config/testers.json` — необязательный заранее разрешённый список `{"ids": [], "usernames": []}` (по умолчанию пуст).

## Формат data.json

Формат прежний; v2 добавляет только **необязательные** поля. Старые файлы читаются как есть,
а файл, записанный v2, читает и старая версия (проверено тестом `test_rollback.py`).

```jsonc
{
  "pages":    [{"title": "🏛 МФЦ / деканат", "text": "…", "links": [{"title": "…", "url": "…"}]}],
  "subjects": [{"name": "Химия", "teacher": "…", "contacts": "…", "description": "…",
                "sections": [{"title": "📖 Учебная литература", "text": "", "links": [],
                              "files": [{"file_id": "…", "name": "лекция.pdf", "mime": "application/pdf"}]}]}],
  "events":   [{"day": 26, "month": 10, "year": 2026, "date": "2026-10-26", "text": "…", "created": "…"}],
  "homework": [{"id": 0, "subject": "Химия", "subject_idx": 3, "text": "…",
                "day": 27, "month": 10, "year": 2026, "date": "2026-10-27",
                "done": false, "created": "…",
                // новое, всё необязательно:
                "kind": "lab",          // нет поля = "hw" (Д/з); "lab" — лаба; "ctrl" — контрольная/тест; "exam" — экзамен/зачёт
                "src": "tuis", "tuis_key": "chem-final",   // запись добавлена из документов ТУИС
                "exam_type": "credit",  // для kind=exam: "exam" | "credit" (зачёт)
                "time": "10:00", "place": "ЕГФ ауд. 375",  // для экзаменов
                "done_at": "…"}],       // когда отмечено выполненным
  // новое (v3, ТУИС), всё необязательно:
  "scores":      {"chem": {"labs": 6, "kr": 15.5}},   // мои баллы: ключ курса → ключ пункта БРС (config/tuis.json)
  "tuis_seeded": ["chem-final", "lat-credit"]        // какие события ТУИС уже добавлены (удалённое не вернётся)
}
```

ТУИС: при запуске хук `on_startup` фичи `scores` один раз добавляет события из `config/tuis.json`
(только будущие или без даты) в `homework`, пропуская дубли (тот же предмет и та же дата, либо
совпадает название в «кавычках»; для экзаменов — тот же предмет и та же дата/без даты).
Старая версия бота покажет `kind: "ctrl"` как Д/з — данные не теряются.
Обновить данные ТУИС: поправить `config/tuis.json` (или генератор `/workspace/tuis/build.py`) и задеплоить.

Нормализация при загрузке такая же, как раньше (порядок предметов, переименование, шаблон
разделов) + выдаёт `id` заданиям без id. Страницы «📅 Расписание» и «📝 Дедлайны и экзамены»
в data.json остаются, но в меню скрыты — их заменили отдельные экраны.

## Откат на старую версию

Старая версия сохранена тегом **`stable-v1`** (коммит `5f8da79`). Версия до интеграции ТУИС —
тег **`stable-v3`** (коммит `fa96138`).

* Локально посмотреть/запустить: `git checkout stable-v1`.
* Откатить прод: `git checkout main && git reset --hard stable-v1 && git push --force-with-lease origin main`
  (или мягко: `git revert` коммитов v2). Railway пересоберёт старую версию; база совместима в обе стороны.
* Тег в GitHub: `git push origin stable-v1`.

## Деплой

Railway: команда запуска та же — `python bot.py`, тот же `requirements.txt`, те же переменные.
Миграции данных не нужны. Деплой = влить ветку `v2` в `main` и запушить:

```bash
git push origin stable-v1          # сохранить тег старой версии
git checkout main && git merge --ff-only v2 && git push origin main
```

Перед пушем: `python -m pytest -q tests`. Бэкап базы в любой момент — `/backup` (владелец).

## Команды

Видимые: /start, /today, /tomorrow, /week, /deadlines, /exams, /subjects.
Скрытые: /menu, /cancel, /status, /backup (два последних — только владелец).
Файл документом → выбрать предмет и раздел. `data.json` документом → восстановление (с бэкапом текущей).
